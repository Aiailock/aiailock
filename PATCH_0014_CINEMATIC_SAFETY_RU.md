# Глобальное обновление 0014 — Cinematic & Safety

Это обновление превращает reader в тёмную кинематографичную книгу и добавляет инструменты, которые помогают безопасно вести большую историю с телефона. Все сообщения WhatsApp, воспоминания, медиа, альбомы, GIF, реакции и настройки из `0013` сохраняются.

## Что добавлено

1. Новый reader в глубоком графитовом цвете с тёплым ivory-текстом и мягкими золотыми акцентами.
2. Более спокойная композиция: меньше карточек и технических рамок, больше воздуха и крупной типографики.
3. Мягкая виньетка, лёгкое зерно и деликатные переходы без кислотного неона.
4. Кинематографичная обложка, экран пароля, главы, паузы между годами и финал.
5. «Продолжить с места»: reader запоминает последнюю прочитанную сцену в браузере читателя.
6. Тонкая полоса прогресса чтения.
7. Название текущей главы закрепляется сверху во время чтения.
8. Новый тип сцены «Цитата» для большой фразы или признания.
9. Новый тип сцены «Пауза» для тихого перехода и эмоционального ритма.
10. Цитаты и паузы создаются и редактируются прямо в мобильной мастерской и в единой истории.
11. Отложенная публикация: можно указать дату и время, когда сцена появится у читателя.
12. Серверная защита расписания: будущая сцена и её медиа недоступны до срока даже по прямому запросу.
13. История версий для изменений сообщений, воспоминаний, скриншотов и элементов timeline.
14. Восстановление предыдущей версии одной кнопкой.
15. Новый раздел Admin → «Сохранность».
16. Проверка потерянных медиа, зависших импортов, дублей, скрытых и запланированных сцен, глав без названия.
17. Скачиваемая JSON-копия основных данных истории.
18. Альбомы, GIF, внешние фоны, реакции, интерактивы, стили дат и WhatsApp-импорт полностью совместимы с обновлением.
19. Улучшена защита от выхода длинного текста за границы на узких экранах.
20. Сохранена поддержка `prefers-reduced-motion`: при отключённой анимации история остаётся красивой и читаемой.

## Важно перед установкой

- Обновление добавочное: оно не удаляет существующие строки и файлы.
- Не запускайте SQL-файл вручную частями. Используйте `supabase db push`, чтобы миграции применились в правильном порядке.
- JSON-копия из раздела «Сохранность» содержит данные и пути к файлам, но не копирует байты приватного Supabase Storage. Для полного аварийного архива отдельно сохраняйте Storage или весь Supabase-проект.
- Реального постоянного подключения к WhatsApp или QR-синхронизации в проекте нет. Импорт остаётся честным и надёжным: обычный экспорт WhatsApp в ZIP.

## Установка поверх версии 0013

### 1. Сделайте резервную точку

Перед обновлением сохраните текущий репозиторий и сделайте backup базы в Supabase Dashboard. Если версия `0013` уже запущена, существующий сайт можно не останавливать.

### 2. Обновите файлы проекта

Если у вас есть файл `0001-Add-cinematic-reader-and-story-safety-center.patch` и текущая версия основана на `0013`, примените его из корня репозитория:

```bash
git am 0001-Add-cinematic-reader-and-story-safety-center.patch
```

Либо распакуйте полный архив `aiailock-cinematic-safety-0014.zip` в новую папку и перенесите свой `.env`. Не заменяйте рабочий `.env` содержимым из архива; в архиве есть только безопасный `.env.example`.

### 3. Установите зависимости и проверьте сборку

```bash
npm install
npm run typecheck
npm run lint
npm test
npm run build
```

### 4. Примените миграцию базы

Из корня проекта:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

Последней должна примениться миграция:

```text
supabase/migrations/0014_cinematic_safety.sql
```

Она добавляет `timeline_elements.visible_from`, типы `quote`/`pause`, таблицу `story_revisions`, функции восстановления и проверки, а также обновляет защищённое reader-представление.

### 5. Обязательно переопубликуйте изменённые Edge Functions

```bash
supabase functions deploy public-timeline
supabase functions deploy get-media-url
supabase functions deploy reader-analytics
supabase functions deploy reader-reaction
```

Остальные функции можно переопубликовать вместе с ними, но для `0014` изменены именно эти четыре.

### 6. Опубликуйте frontend

Если Netlify подключён к GitHub, отправьте обновление в свою рабочую ветку и запустите Deploy. При ручной публикации:

```bash
npm run build
```

Публикуемая папка — `dist`.

Переменные Netlify не меняются:

```text
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

### 7. Быстрая проверка после установки

1. Войдите в `/admin/login`.
2. Откройте «Сохранность» и нажмите «Проверить снова».
3. Скачайте первую JSON-копию.
4. В «Добавить» создайте тестовую цитату и паузу.
5. Создайте ещё одну сцену с показом через несколько минут.
6. Откройте Preview: тестовая будущая сцена не должна быть видна раньше срока.
7. Измените текст, затем откройте «Сохранность» и проверьте, что появилась версия с кнопкой восстановления.
8. На телефоне прокрутите несколько сцен, перезагрузите страницу и проверьте кнопку «Продолжить с места».
9. Проверьте внешнюю фоновую картинку, альбом, GIF, видео/аудио и реакцию.
10. Проверьте ширины примерно 320, 390 и 430 пикселей.

## Как пользоваться новыми функциями

### Цитата и пауза

Admin → «Добавить» → «Цитата» или «Пауза». У цитаты основной текст становится крупной центральной фразой, а поле названия — автором или короткой подписью. Пауза может быть полностью без текста.

### Отложенная публикация

В мобильной мастерской заполните «Открыть автоматически позже». В единой истории расписание доступно у каждой сцены через кнопку «Показать позже». Если очистить дату и сохранить, сцена снова показывается сразу.

### История версий

После изменения текста, даты, оформления или видимости откройте Admin → «Сохранность». В блоке «Последние изменения» выберите нужную запись и нажмите «Вернуть эту версию».

История версий начинает накапливаться после установки `0014`; изменения, сделанные до миграции, в неё не попадут.

### Резервная копия

Admin → «Сохранность» → «Скачать копию». Полученный файл `aiailock-backup-YYYY-MM-DD.json` храните отдельно от сайта. Он полезен для аудита и переноса данных, но не заменяет backup приватных файлов Storage.

### Продолжение чтения

Позиция хранится локально в браузере читателя. Она не раскрывает личные данные и не требует аккаунта. Кнопка появляется после того, как прочитано больше первых трёх элементов. На другом устройстве позиция начинается заново.

## Откат

Frontend можно откатить на предыдущий коммит без удаления данных. Миграцию `0014` лучше не откатывать: новые поля и таблица не мешают старому frontend. Если уже созданы сцены `quote` или `pause`, старый reader их не оформит, поэтому перед временным откатом их рекомендуется скрыть.

Не удаляйте `story_revisions` и `visible_from` на рабочей базе без отдельного backup.
