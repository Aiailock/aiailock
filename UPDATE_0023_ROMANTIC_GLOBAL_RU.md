# Глобальное романтическое обновление 0023

Это полное обновление проекта **aiailock / «Для тебя»** поверх актуального состояния GitHub. Главная цель — чтобы история читалась как тёплое личное письмо: нежно, красиво, живо и романтично, но без выдуманных событий или чувств от имени другого человека.

Обновление добавочное. Оно не очищает сообщения, медиа, воспоминания, статистику или настройки.

## Главное, что изменилось

### 1. ИИ-режиссёр больше не предлагает только паузы

- Для каждого подходящего места строится **2–3 разных варианта**.
- Варианты разделены по смыслу: нежный текст, живая эмоция с GIF, настоящая фраза из истории или кинематографичная сцена.
- Если облачный ИИ вернул только паузы или неполный JSON, приложение само дополняет набор разнообразными безопасными вариантами.
- Каждый набор относится к одному месту истории; по умолчанию выбирается один лучший вариант, а не все сразу.
- Добавлены понятные метки вариантов, причины предложения и уровень уверенности.
- В режимах «Бережно», «Сбалансированно» и «Кинематографично» меняется насыщенность, но не достоверность истории.
- Промпт запрещает приписывать ей несуществующие слова, мысли и реакции.
- Увеличен запас ответа Edge Function, чтобы несколько вариантов не обрезались.
- Добавлены 7 автоматических тестов логики режиссёра.

### 2. Исправлен поиск GIF, где библиотека показывала 0

- Поиск Wikimedia теперь сразу запрашивает MIME-тип `image/gif`, а не пытается найти GIF среди случайных картинок постфактум.
- Русские запросы вроде «объятия», «скучаю», «спокойной ночи», «сердечки», «поддержка» автоматически получают подходящий английский вариант для международной библиотеки.
- Оригинальный и переводной запрос выполняются вместе; результаты объединяются без дублей.
- Если точный запрос ничего не дал, включается дополнительный безопасный поиск GIF.
- Добавлены быстрые милые категории: **объятия, сердечки, спокойной ночи, скучаю, смешное, поддержать**.
- Защита от гонки запросов не позволяет старому медленному ответу перезаписать новые результаты.
- Выбранная ИИ-режиссёром GIF скачивается и сохраняется в приватный Supabase Storage до предпросмотра.
- В опубликованной истории используется приватная копия, поэтому внешняя ссылка больше не является единственной точкой отказа.
- При отмене постановки черновика его временная приватная GIF очищается.

### 3. Админка стала удобнее на телефоне

- В меню «Ещё» появился поиск по всем разделам.
- Добавлены быстрые действия **«Продолжить черновик»** и **«Проверить Reader»**.
- Все 14 разделов остаются доступны с телефона и сгруппированы по назначению.
- Последняя открытая вкладка сохраняется и имеет собственный адрес через hash.
- Появился понятный индикатор отсутствия сети.
- Черновики остаются локально на устройстве; публикация явно откладывается до восстановления сети.
- Кнопки и горизонтальные подборки рассчитаны на управление большим пальцем и не требуют точного попадания.

### 4. Новые романтические функции

- В быстрой мастерской появились шесть заготовок:
  - «Объятие через экран»;
  - «Письмо на грустный день»;
  - «Милый вопрос» с четырьмя вариантами;
  - «Между строк»;
  - «Та самая фраза»;
  - «Ночное сообщение».
- Заготовки намеренно остаются редактируемыми: их нужно персонализировать правдивыми деталями вашей истории.
- В конце Reader добавлено личное завершение с интерактивным сердечком и обещанием продолжения.
- Реакции и мнения теперь сохраняются сначала на телефоне, а при возвращении сети автоматически отправляются в Supabase.
- Благодарность после реакции стала мягче и теплее.

## Какие ошибки были найдены

| Ошибка | Причина | Исправление |
|---|---|---|
| ИИ предлагал только «паузу» | Локальный fallback создавал один тип, а неполный ответ модели не дополнялся | Новый генератор вариантов и автоматическое дополнение набора |
| Для одного места выбиралось слишком много сцен | Все предложения отмечались одновременно | Один рекомендованный вариант на точку, ручной выбор через radio |
| Поиск GIF показывал 0 | Wikimedia сначала возвращала обычные файлы, а код затем отбрасывал не-GIF | Серверный MIME-фильтр, перевод эмоциональных запросов и fallback |
| Быстрый повтор поиска показывал старые результаты | Ответы сети приходили в другом порядке | Идентификатор актуального запроса |
| GIF могла исчезнуть после публикации | ИИ-сцена зависела от внешнего URL | Копия в приватном Storage и связанная запись memory |
| Приватная AI-GIF могла создать конфликт двух timeline-строк | Триггер memories уже создаёт единственную строку автоматически | Миграция переиспользует строку триггера и только переводит её в скрытый preview |
| Реакция терялась без сети | Отправка происходила только напрямую в Edge Function | Локальная очередь и повторная синхронизация |
| На телефоне трудно найти редкую вкладку | Длинный список разделов без фильтра | Поиск и быстрые действия в мобильном меню |
| Конец истории выглядел технической заглушкой | Был только общий блок «продолжение следует» | Личное интерактивное завершение |

## Перед обновлением

Сохраните текущий рабочий код отдельной веткой:

```bash
git branch backup-before-0023
```

Не удаляйте `.git`, `.env` или `.env.local`. Не добавляйте секреты в GitHub.

## Полный передеплой Supabase → GitHub → Netlify

### Шаг 1. Заменить проект

Распакуйте архив поверх корня локального репозитория. В архиве нет `.git`, `node_modules`, `dist` и секретных `.env`.

Затем:

```bash
npm install
npm test
npm run typecheck
npm run lint
npm run build
```

### Шаг 2. Применить миграцию Supabase

```bash
npx supabase@latest login
npx supabase@latest link --project-ref ВАШ_PROJECT_REF
npx supabase@latest migration list
npx supabase@latest db push
```

Должна примениться миграция `0023_romantic_director_gif_library.sql`. Она добавляет две колонки и обновляет только функции постановки/отмены AI-черновиков.

Если CLI сообщает о несовпадении истории миграций, не выполняйте `migration repair` наугад. Сохраните вывод `migration list`: по нему нужно подбирать точную команду, не рискуя данными.

### Шаг 3. Опубликовать Supabase Edge Function

Для 0023 обязательна одна функция:

```bash
npx supabase@latest functions deploy ai-director
```

Если после прошлых обновлений функции публиковались не все, можно безопасно развернуть полный набор:

```bash
npx supabase@latest functions deploy import-zip
npx supabase@latest functions deploy process-ai
npx supabase@latest functions deploy get-media-url
npx supabase@latest functions deploy public-timeline
npx supabase@latest functions deploy reader-access
npx supabase@latest functions deploy reader-analytics
npx supabase@latest functions deploy reader-reaction
npx supabase@latest functions deploy ai-director
npx supabase@latest functions deploy reader-interaction
```

### Шаг 4. Отправить код в GitHub

Проверьте, что секреты не попали в список:

```bash
git status --short
git diff --check
git add .
git commit -m "Romantic global update 0023"
git push
```

На телефоне команды удобнее выполнять в **GitHub Codespaces**: репозиторий → **Code** → **Codespaces** → создать/открыть codespace. `github.dev` подходит для редактирования файлов, но полноценного терминала в нём нет.

### Шаг 5. Дождаться Netlify

Если сайт уже связан с GitHub, push запускает deploy автоматически. Если не запустился: Netlify → **Deploys** → **Trigger deploy** → **Deploy site**.

Настройки:

```text
Build command: npm run build
Publish directory: dist
Node version: 20
```

В Netlify нужны только:

```text
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

Никогда не добавляйте в `VITE_` переменные `SUPABASE_SERVICE_ROLE_KEY`, AI/OpenRouter-ключ или `READER_ACCESS_SECRET`: браузерные переменные публичны.

## Проверка после публикации

1. Откройте `/admin/login` на телефоне и войдите.
2. В «Ещё» найдите через поиск «ИИ-режиссёр» и «Настройки».
3. Откройте «ИИ-режиссёр», выберите сбалансированный режим и создайте предложения.
4. У одной точки должны быть разные варианты, включая GIF там, где она уместна.
5. Откройте поиск GIF, нажмите «Объятия» или «Сердечки»: счётчик не должен оставаться нулевым при доступной Wikimedia.
6. Выберите GIF, подготовьте preview, опубликуйте и откройте Reader.
7. Включите авиарежим, оставьте реакцию, верните сеть и обновите страницу — реакция должна синхронизироваться.
8. Дойдите до конца истории и проверьте интерактивное сердечко.

## Откат

Интерфейс можно вернуть через backup-ветку. После применения миграцию `0023` удалять или помечать `reverted` не нужно: добавленные колонки не мешают старому интерфейсу. Самый безопасный способ для уже опубликованного коммита — создать обычный revert-коммит:

```bash
git log --oneline -5
git revert ХЕШ_КОММИТА_ОБНОВЛЕНИЯ
git push
```
