## Что изменилось

1. Открытый reader получает уведомления о сохранённых изменениях через Supabase Realtime.
2. Резервная проверка версии каждые 5 секунд, когда вкладка видима; повторная проверка при возвращении во вкладку и восстановлении сети.
3. Обновляются тексты, стили, публикация/скрытие, удаления, порядок и добавления в загруженном участке истории.
4. Настройки reader, заголовок и оформление обновляются без перезагрузки страницы.
5. Обновление старается сохранить видимую запись и её положение; если запись удалена, использует соседнюю видимую. Если во время запроса читатель сам прокрутил страницу, принудительного возврата нет.
6. После перехода к далёкой главе обновляется загруженный участок, а не вся история с начала.
7. Позиция при переходе к главе заново вычисляется сервером, чтобы счётчик не опирался на старое место записи.
8. Замена файла/ссылки у существующего медиа обновляет источник в reader и сбрасывает прежнюю ошибку загрузки.
9. В Preview отображается состояние подключения автообновлений.
10. Новый раздел админки «Слова для неё» в группе «Контент» и мобильном меню «Ещё».
11. 72 готовых пожелания, написанных на русском, без платных API и запуска ИИ.
12. Шесть категорий: новый день, горжусь тобой, когда тяжело, отдых и забота, я рядом, вечер.
13. Поиск по тексту заготовок.
14. Избранные заготовки сохраняются в этом браузере.
15. Случайное пожелание из выбранной категории и текущих результатов поиска.
16. Вставки перед началом дня и после последней записи дня; после одного дня означает между ним и следующим.
17. Несколько вставок у одного места, с постоянным порядком создания.
18. Редактируемые заголовок, текст и подпись; ограничения длины и счётчик символов.
19. Четыре оформления: письмо, ночное небо, рассвет, тихие слова.
20. Предпросмотр настоящего текста и оформления рядом с редактором.
21. Локальное восстановление набираемого текста после перезагрузки админки.
22. Серверные черновики: можно сохранить, не показывая ей; отдельный переключатель публикации.
23. Редактирование, копирование в новый черновик, удаление и переход к месту вставки в Preview.
24. Кнопка «Сохранить тепло» в reader: личная отметка на этом устройстве, без отправки в аналитику.
25. Исправлена очистка статистики: прежние открытые вкладки не восстанавливают удалённые записи.
26. «Удалить мои посещения и не учитывать меня»: исключается текущий браузер, остальные читатели сохраняются.
27. Можно удалить и исключить отдельное устройство, а затем вернуть его учёт.
28. При полном сбросе реакции и ответы сохраняются по умолчанию. Удаление — отдельный осознанный выбор.
29. После очистки показывается количество удалённых устройств и посещений. Ошибка запроса больше не оставляет кнопку навсегда в состоянии «Очищаю».
30. Нейтральные подписи аналитики: устройство не выдаётся за подтверждённую личность читателя.

## Что происходит с историей

Миграция 0027 не меняет даты, display_order, тексты, медиа или существующие главы. Она не запускает старое обновление 0026 и не переупорядочивает историю. Пожелания хранятся отдельно и привязываются к ID существующей записи.

Выбор дней строится по текущему порядку опубликованных записей: новая дата или явная глава начинает новый раздел. Даты отображаются в часовом поясе браузера. Скрытые и ещё не наступившие запланированные записи не предлагаются как места новой вставки.

Если позже перенести опорную запись, пожелание последует за ней. Если добавить новые записи после ранее выбранного конца дня, для переноса пожелания в новый конец выбери день заново и сохрани. Скрытие опорной записи скрывает и её пожелания. Удаление опорной записи удаляет связанные пожелания. В галерее пожелания отображаются перед/после всей группы фотографий.

## Установка с телефона через GitHub Codespaces

### 1. Открыть настоящий терминал

Открой репозиторий GitHub → Code → Codespaces → существующий Codespace или Create codespace on main.
Обычный github.dev не подходит для этих команд: нужен Codespaces с Terminal → New Terminal.
Загрузи `aiailock-0027-live-support.zip` в корень проекта через Explorer → Upload.

В терминале перейди в корень:

```bash
cd /workspaces/aiailock
unzip aiailock-0027-live-support.zip
python3 aiailock-0027-update/install.py
```

Если рабочая папка называется иначе, используй её имя. Установщик должен запускаться из корня Git-репозитория. Он не заменит файлы, которые отличаются от проверенной версии. При сообщении о несовпадении остановись и сохрани текст ошибки — не применяй принудительное копирование.

Перед установкой сохрани свои незакоммиченные изменения. Установщик требует чистые отслеживаемые файлы, но загруженный ZIP и распакованная папка ему не мешают. Резервная метка будет напечатана после проверки. Она сохраняет код до установки, а не содержимое базы Supabase.

### 2. Проверить сборку

```bash
npm ci
npm run build
node --import tsx scripts/test-live-window.ts
```

Не продолжай, если сборка завершилась ошибкой.

### 3. Применить только новую SQL-миграцию

Открой `supabase/migrations/0027_live_support_analytics.sql` в Codespaces, скопируй весь файл.
Открой свой проект Supabase → SQL Editor → New query → вставь → Run.
Запусти один раз. В файле есть BEGIN/COMMIT: при ошибке изменения этой миграции должны откатиться целиком.

Старые миграции заново не запускай. Нумерация намеренно переходит с 0023 на 0027: отсутствующие 0024–0026 создавать не нужно.
Этот путь через SQL Editor не требует менять историю старых миграций и не использует `migration repair` или очистку БД.
Если позже используешь `supabase db push`, учти: SQL Editor сам не отмечает файл как применённый в журнале CLI; не запускай его повторно через CLI без согласования журнала.

### 4. Обновить две Edge Functions

В Supabase → Project Settings найди Reference ID именно проекта этого сайта. Это не API-ключ.
В терминале Codespaces:

```bash
npx supabase@latest login
read -r -p "Вставь Reference ID проекта Supabase: " SUPABASE_PROJECT_REF
npx supabase@latest functions deploy public-timeline --project-ref "$SUPABASE_PROJECT_REF"
npx supabase@latest functions deploy reader-analytics --project-ref "$SUPABASE_PROJECT_REF"
```

В репозитории уже есть нужный `supabase/config.toml`. Обе функции проверяют доступ к reader в своём коде. Новые секреты или платные сервисы не требуются.
Не публикуй frontend, если миграция или одна из двух функций завершились ошибкой.

### 5. Отправить код в GitHub → Netlify

После успешных шагов 2–4:

```bash
git add src supabase scripts/test-live-window.ts UPDATE_0027.md
git diff --cached --stat
git commit -m "Add live reader, support studio and reliable analytics reset"
git push origin main
```

Если Codespace открыт не на main, сначала проверь `git branch --show-current` и отправляй/сливай ту ветку, к которой подключён Netlify. Не используй force push.

Netlify, подключённый к этой ветке, начнёт сборку автоматически. В Deploys дождись Published. Затем один раз обнови reader и админку, чтобы они загрузили новый код. В дальнейшем сохранённый контент будет обновляться сам.

В Git не нужно добавлять ZIP, распакованный установщик, node_modules, dist, .env и генерируемый tsconfig.tsbuildinfo. Не используй `git add .` для этой установки.

## Как пользоваться пожеланиями

1. Админка → Ещё/Контент → Слова для неё.
2. Выбери день и «Перед началом дня» или «После последней записи дня».
3. Выбери заготовку или напиши свой текст, измени подпись и оформление.
4. Проверь предпросмотр.
5. Для публикации включи «Показывать в reader после сохранения» и нажми «Сохранить и опубликовать».
6. Для следующего пожелания нажми «Новая вставка». Существующее можно скопировать в новый черновик.

Сохранённый черновик не виден в reader, в том числе в отдельной reader-вкладке Preview. Его внешний вид виден в редакторе студии.

## Как убрать только свои посещения

На том же браузере, с которого ты проверял reader: Админка → Чтение → Мои проверки сайта → «Удалить мои посещения и не учитывать меня» → подтверждение.

Если ты открывал сайт в другом браузере/на другом телефоне, это отдельное устройство. Найди его в списке и выбери «Удалить и исключить устройство». Сайт не может достоверно определить, кому принадлежит чужой браузер. После очистки cookie браузер получит другой ID.

Чтобы начать статистику с нуля для всех: Чтение → Очистить. Реакции/ответы по умолчанию остаются. Старые вкладки перестанут отправлять прогресс до нового открытия страницы. Устройства, исключённые отдельно, останутся исключёнными и после общего сброса.

## Проверка на твоём сайте после установки

- Открой reader и админку в разных вкладках или на двух устройствах. Измени текст опубликованной записи, сохрани: reader должен обновиться без перезагрузки.
- Проверь вставку перед днём и после него, затем скрой одну из вставок.
- Замени ссылку/файл медиа в существующей записи и проверь обновление источника.
- В Preview сверху должна появиться подпись автообновления. При проблеме проверь, что применена 0027.
- После удаления своих посещений прокрути старую вкладку reader и снова обнови аналитику: удалённые посещения не должны вернуться.
- Для проверки нового настоящего посещения используй не исключённый браузер и заново открой reader.

Realtime обычно начинает обновление сразу после сохранения; резервная проверка — раз в 5 секунд. К этому добавляется время получения страниц с сервера. Без сети мгновенные изменения невозможны. Незасохранённый набор текста в админке не публикуется. Это синхронизация контента; новые версии кода по-прежнему требуют деплоя.
